## 3. Project Summary

The team built a simple Task Management App (HTML, CSS, JavaScript) that lets users create tasks, view them in one place, and track progress through To Do, In Progress, and Done stages. Deliverables included the README, requirements and user stories, SRS document, workflow diagram, wireframe, prototype, test cases, and defect report.

---

## 4. What Went Well

- **Clear roles:** Every member had a defined role (Project Manager, Requirements Analyst, System Designer, Documentation Lead, Developer, Tester), so responsibilities were easy to understand.
- **Strong requirements:** The requirements file with functional and non-functional requirements, user stories, and acceptance criteria gave the whole team a shared reference.
- **Right SDLC choice:** The Agile model supported incremental development, regular progress checks, and continuous testing.
- **Organised repository:** A consistent project structure on GitHub (`README.md`, `requirements.md`, `src/`, test cases, defect report) made files easy to find.
- **Effective tracking:** GitHub Projects and Jira helped assign issues, set priorities, and monitor progress.
- **Teamwork and communication:** Members supported each other and shared updates, which kept work moving.
- **Early testing:** Test cases were prepared and executed against the prototype, and defects were recorded for correction.
- **Focused scope:** Keeping the prototype to basic task creation, viewing, and status updates helped us finish on time.

---

## 5. Challenges Faced

- **Tight timeline:** Completing documentation, design, development, and testing in a short time put pressure on everyone.
- **Scope management:** Ideas such as authentication, reminders, priorities, and search had to be postponed to avoid scope creep.
- **Dependencies between roles:** The developer and tester had to wait for requirements, design, and wireframes to be finalised before they could proceed.
- **Using two tools:** Keeping GitHub Projects and Jira in sync required extra effort and sometimes caused duplicate or outdated entries.
- **Version control practice:** Some members were still learning Git, which led to merge conflicts and unclear commit messages.
- **Documentation consistency:** Keeping the README, requirements, SRS, and test cases aligned as details changed was difficult.
- **Limited testing:** Testing was manual and covered only basic scenarios, so some edge cases may have been missed.
- **Basic prototype:** The prototype stored limited data and lacked features such as login, deadlines, and search.

---

## 6. Improvements for Next Time

| Area | Improvement |
|------|-------------|
| Planning | Break work into short sprints with clear goals and a realistic timeline. |
| Scope control | Freeze the MVP scope early and maintain a prioritised backlog for new ideas. |
| Communication | Hold short daily stand-ups and a sprint review to share progress and blockers. |
| Collaboration | Let design, development, and testing start in parallel using draft requirements. |
| Tool usage | Pick one main tracker for tasks (or link GitHub issues to Jira keys) to avoid duplication. |
| Version control | Use feature branches, pull requests, code reviews, and meaningful commit messages. |
| Documentation | Review all documents together before each release so they stay consistent. |
| Testing | Add edge-case and negative test cases; consider automated testing in future. |
| Quality | Define a "Definition of Done" for each task covering code, testing, and documentation. |
| Skills | Hold a quick Git and Jira walkthrough at the start of the project. |

## 8. Lessons Learned

- Clear requirements and roles save time later in the project.
- Small, incremental deliveries make progress visible and reduce risk.
- Good communication and consistent documentation are as important as good code.
- Regular retrospectives help the team improve with every iteration.

---

## 9. Conclusion

The team delivered a working Task Management App along with complete project documentation by following Agile practices and collaborating through GitHub and Jira. The challenges around time, scope, tooling, and testing gave us practical lessons we will apply in future projects.
